## Текущий результат (algo_eval4)

`cd tools/algo && ALGO=milan ./algo_eval4 N` / `ALGO=chicago ./algo_eval4 N`.
Галерея — первые N пригодных natural, ёмкость сессии `*(int16*)(sess+8)=20` как у EA (81, env SESSCAP), одна проба = один кадр = одна попытка, свежая
копия галереи (unpack) на каждую пробу. Калибровка — один фон-кадр, kr нейтральный 8192
(лог `cali B … framenum=0`). Вызовы — как в 00 «Эталонный конвейер».

## Открытый порт MR !648 против DLL ([docs/mr648-port-eval.md](../../../../docs/mr648-port-eval.md))

`tools/algo/port_eval.sh 12` (`FIXES=1` — с `port_preprocess_fixes.patch`), тот же протокол, N=12:

| вариант | natural | varied | impostor |
|---|---|---|---|
| порт как есть | 8/17 | 10/25 | **1/97** |
| порт + 2 правки препроцессора | 15/17 | 14/25 | **4/97** |
| порт + правки + WARM (impostor) | 16/17 | 17/25 | 0/97 |
| DLL Chicago + WARM (impostor) | 15/17 | 10/25 | 0/82 |

- Порт НЕ эквивалентен DLL: препроцессор совпадает бит-в-бит только до адаптации (кадр 0);
  ошибки порта: множитель после 30 кадров `(m·30+r)/30` вместо `(m·29+r)/30`; на кадрах 1–3 DLL
  держит единичное усиление; kr не сохраняется в `chicago-calibration.dat`; порт обновляет состояние
  на каждом кадре, DLL — только после своих проверок качества (условие не разобрано).
- Матчер порта мягче: почти все его совпадения — без индекса подшаблона (fallback-ветка, у DLL
  совпадение требует idx ≥ 0), отсюда ложные принятия чужих; порогом по score не отсекается.
- DLL (winpe) — эталон для исправления порта: можно сверять вход/выход каждой стадии.

## Проверено

- Вендорские аргументы вместо отклонений (`NOUNPACK`/`PARAMZERO`/`BYTE0`/`PURPOSE0`/`EADD_O3`)
  дают небольшой плюс на Milan/10 (natural 8 → 10).
- Транспонирование кадра + gimg `+0x08=80, +0x0a=64`: вендорская quality ≈ 70 (без
  транспонирования ≈ 6.7), self-match ratio 101.
- algo_eval3 (layout 3, param = нули — не вендорские аргументы): синтетический сдвиг и поворот
  ≤ 6°, а также ровно 180° — совпадение, зеркальное отражение — нет; `PAIRS` (identifytemplate,
  шаблоны из одного кадра): свой 154/2862 (5.4%), чужой 0/4428.

## Проверено и НЕ помогает

- `PERBG` — калибровка фоном каждого касания.
- `STUDY` — templateStudy + repack после каждого совпадения.
- `MAXT` (аргумент enrolStartEx) — без эффекта; реальная ёмкость — `sess+8` (int16, по умолчанию 8,
  EA ставит 20). С SESSCAP=20 шаблон содержит N записей (12/15/20), без него — всегда 8.

## Открытые вопросы

- Калибровка — разобрана в [80-calibration](80-calibration.md): фон b = один кадр без пальца (gfusb),
  kr обучается онлайн, blob сохраняется в файл. Проверено экспериментально (WARM).
- Протокол регистрации EA — разобран в [81-enroll-protocol](81-enroll-protocol.md) (12 касаний, пороги
  quality ≥ 25 / coverage ≥ 65, overlay-подсказки, best-of-2 кадра на касание). В offline-замере пока
  применена только ёмкость 20; отбор кадров по overlay/best-of-2 — не воспроизведён.
- Внутренности AlgoChicago (тип шаблона 24, шкала score ≈ 38..77) не разобраны.
- Что Windows читает тот же регистр chip id, что probe.py — не проверено (см. 30).
- Смысл probe+0x148 («водяной знак» в LSB первой строки) — гипотеза.
