## Как воспроизвести

```sh
cd tools/algo
./oracle_feat.sh /tmp/d12 12                    # /tmp/d12.{feat,proc,proc.cbuf,txt}
FEAT_DUMP=/tmp/p12.feat MFIXES=1 FFIXES=1 INJECT_PROC=/tmp/d12.proc VERBOSE=1 ./port_eval.sh 12 > /tmp/p12.txt
./cmp_feat.py /tmp/d12.feat /tmp/p12.feat [--mode enroll]   # первое расхождение: проба, поле, индекс
./cmp_match.py /tmp/d12.txt /tmp/p12.txt
WARM=1 WARMSET=impostor ...                     # то же с прогревом (и для oracle_feat.sh)
FEAT_DUMP=... MFIXES=1 FFIXES=1 OPENPP=1 VERBOSE=1 ./port_eval.sh 12   # без INJECT, препроцессор openchicago
```

- `algo_eval4 DUMP_PROC=<f>` теперь пишет и `<f>.cbuf` — `{int32 rec; cbuf[0..15]}` на вызов
  препроцессора (формат `<f>` не менялся). `port_eval` с FFIXES и INJECT_PROC берёт оттуда
  контекст cbuf[0..5], а quality/coverage — из заголовка дампа.
- С FFIXES проходы WARM в `port_eval` гоняют только препроцессор (DLL зовёт getFeature лишь из
  enrolAddImage/identifyImage — у getFeature есть межкадровое состояние); галерея — режим enroll.

## Порядок getFeature (тип 24) и правки патча

Адреса — наша DLL (у порта в комментариях +0x9b0).

1. **0x180053440 — метка в LSB первой строки** (пишет 0x180054270 препроцессора): код разрешения и,
   при бите столбца 74, план «региона» (LSB всех пикселей ниже строки 0). Порт брал
   packed_resolution из собственного анализа сырого кадра — отсюда 29/127 расхождений PRES.
   Классы 0x180052210 / 0x1800536d0 (таблица 1..9 → 2,2,3,0,1,2,4,5,5), cbuf[3] > 0 заменяет класс 2.
2. **Контекст cbuf[0..5]** (0x180052310) — байты буфера препроцессора, в порте не было. Пишет их
   0x180043c70 (описан в docs/stage1-preprocess.md, п. 12); реализован в openchicago.
3. **0x180012df0 — live auxiliary и итоговый packed_resolution с межкадровым состоянием**
   (глобалы 0x1800ca198 счётчик истории, 0x1800ca19c прошлый coverage, 0x1800d8750/54 счётчик и
   уровень, 3 кадра истории 0x1800ca1a0 по 0x4c90): компоненты тёмных (<0x80) и светлых в маске
   пикселей (4-связная разметка 0x180055720 с очередью 0x992, выбор 3 крупнейших > 350 px
   0x180055b20; при 3 кадрах истории — устойчивые компоненты 0x180015980), заполнение щелей по
   таблице 3×3 0x180017430, счёт тёмных < 30; правила уровня/пика, запись истории при coverage ≥ 75.
   В порте был stateless `build_live_auxiliary` (peak_state, класс + 4).
4. **0x180010b30 — второй проход**: если собрано ≤ 60 кандидатов, градиентный вход строится
   ядрами селекторов 100/101 (таблица 0x180092860) и кандидаты собираются заново (масштабное
   пространство типа 24 от прохода не зависит). В порте не было.
5. **0x180014e60 — отвергнутые экстремумы**: сила берётся из кандидата после уточнения (она
   обновляется до проверки детерминанта), добавляются только при count < 60 **и quality > 80 и
   coverage > 80**. Порт брал сырой отклик и добавлял без условий.
6. **0x180011a50 — классификация статусов**: кроме status > 0 голосуют записи с аннотацией < 30
   при cbuf[0] > 2 и < 20 при cbuf[0] > 1; без голосов F+0x158..0x160 не меняются (identify
   переиспользует объект F — значения прошлой пробы; enroll — свежий нулевой объект).
7. **0x180036c70 / 0x18003b2d0 — фильтр по плану региона** (после фильтра маски): если нулевых
   пикселей плана ≥ 50, удаляются записи с > 1 нулевым пикселем в окне 5×5. В порте не было.
8. **0x180015cd0 — упаковка записи в режиме identify**: дополнительно +0x24 = слово +0x20 с
   обратным порядком бит и +0x30..+0x37 = «сдвинутый» хвост. Порт оставлял нули, а его матчер
   читает probe+0x24/+0x30 (вариант 180°) — сравнивал с нулями.
9. **0x180016680 — соседи**: при классе плотности 0 все rec+0x39 = 0; при классе 1 — вторые
   аннотации по подготовленной картинке и снятие статуса (F+0x164 > 30, доля > 65, вторая
   аннотация > 65, rec+0x39 > 35).

Без изменений совпали с DLL: маска 0x180050000, подготовленная картинка 0x180055010, источник,
масштабное пространство, градиенты, дескрипторы, аннотации 0x1800163e0, фильтр маски 0x180011940,
разбиение 0x18000e890, карты метрик 0x180054510.

## Что осталось по признакам

- ~~cbuf[0..5] без INJECT~~ — **закрыто**: openchicago строит контекст 0x180043c70
  ({состояние, флаг hold 0/2, счётчик, код класса, (маска·100+50)/N, 0}) с историей в объекте
  препроцессора; `port_eval` с OPENPP берёт его вместо приближения
  `goodix_chicago_feature_preprocessor_context()` (то давало 120/127: LAUX 7, PRES 3; причины —
  неверное состояние пика анализа, класс 3 от «остатка» 0x180037df0 и доля маски). Сверка:
  openchicago/tests (155/155 в A и B + fuzz внутренних функций), `FEAT_DUMP=… MFIXES=1 FFIXES=1
  OPENPP=1 ./port_eval.sh 12` против `oracle_feat.sh` — 127/127 и 12/12, WARM impostor 124/124 и
  12/12, решения совпадают с DLL (cmp_match: 0 расхождений). Приближение осталось только для
  сборки порта без OPENPP.
- Состояние getFeature — статическое в runtime.c (как глобалы DLL); для драйвера его нужно
  сбрасывать/хранить вместе с сеансом (`goodix_chicago_runtime_reset_feature_state()`).
- Не покрыты датасетом: типы кроме 24, cbuf[1] = 2 (флаг hold, 7-й аргумент preprocessor = 1;
  в контексте проверен fuzz-тестом, в getFeature — нет).
