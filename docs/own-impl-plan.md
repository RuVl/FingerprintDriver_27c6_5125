# План: собственная открытая реализация алгоритма ChicagoHS (без DLL)

Решение пользователя (2026-09-28): пишем своё, DLL в продукт не входит — только эталон для
сверки (`tools/algo/winpe.c` + `algo_eval4.c`). Драйвер из MR !648 на железе — позже.

## Принципы

- Цель — **побайтное совпадение с AlgoChicago.dll** (профиль 12) на каждой стадии, на всём
  датасете `dumps/dataset` в хронологическом порядке (адаптивное состояние важно).
- Код порта из MR !648 (`upstream/libfprint-mr648/.../chicago/`, LGPL-2.1+, © Berke Kabagöz)
  берём как основу там, где он совпадает с DLL; SPDX/копирайт сохраняем; расхождения
  исправляем по дизасму. Никакого закрытого кода.
- Каждая стадия: оракул (DLL, внутренние функции через winpe) → дамп входа/выхода → наш код →
  автоматическая сверка (тест). Стадия считается готовой только при 100 % совпадении
  (или обоснованном, задокументированном отличии, не влияющем на решение).
- Итоговое качество мерить тем же протоколом, что `algo_eval4` (галерея 12, WARM на чужих,
  свежая копия галереи на пробу). Требование: FAR 0 на датасете, TAR ≥ DLL.

- Наш код алгоритма: `openchicago/` (создаётся на стадии 1), тесты-сверки: `openchicago/tests/`.
