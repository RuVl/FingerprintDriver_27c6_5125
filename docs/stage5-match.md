## 0x180019800 (тип 24; rsi = &status, rdi = &conf)

```
если status == 0 или conf == 0: 0x1800258c0(rec, q, c, params, 0 /*без штрафа за покрытие*/, &c', &s', NULL);
                                status |= s'; conf |= c'
если status == 0:               0x180023340(rec, q, c, params, &conf, &s'); status |= s'   (conf перезаписывается)
если conf != 0:                 0x180019a30(rec, params, &conf)          — правила, гасят conf
если status != 0:               0x18001fdd0(rec, params, &conf, &status) — правила, гасят status/conf
```

Вызов из планировщика (0x180029878..0x18002993f): после первой оценки 0x1800258c0 (со штрафом) —
**пропуск**, если `conf == 2 && aux ≤ 1 && (agreement ≥ 205 || q ≤ 90) && normalized_coverage ≥ 105`
(aux = [rbp+0x160] = `scheduler_auxiliary.auxiliary_count`); иначе 0x1800535b0 (study-метрики),
0x180019800 и «special && study_metric_20 < 175 → оба флага 0». На пути пропуска 0x1800535b0 не
вызывается — у записи study-метрики остаются нулями (порт считал их всегда; теперь обнуляет).

params (0x18002f300, flag 0, studyflag 1; снято на входе 0x180019800): +0 = +4 = 0 (сдвиги порогов),
+0x3c = 24, +0x40 = 1, +0x44 = 0, +0x48 = packed_resolution пробы, +0x4c = 1. Перенос сделан для этого
профиля (ветки других типов и params+0x40 = 0 не нужны драйверу и не переносились).

0x180023340 (профиль params+0x40 ≠ 0): штраф `5·((g0 < 4) + penalty_flag_b)` при `g4 ≤ 10 || g0 < 4`;
индекс k = clamp(g4 − 4, 0, 9); пороги study_min = {∞,207,205,202,201,195,185×4}, agreement_min =
{∞,203×4,202,201,200,192,184}, coverage_min = {∞,95,88,82,75,65,55×4} (.rdata 0x18007a070, 0x180079fd0,
0x180079f40). `*out = (study ≥ Ts[k] && agr ≥ Ta[k] && cov ≥ Tc[k])`; затем `conf = 1, out |= 1`, если
`(g0 ≥ 6 || g4 ≥ 16 || (g0 ≥ 5 && matched% > 55 && cov ≥ 125)) && study ≥ Ts[k] + 2 && agr ≥ 206 &&
cov ≥ min(Tc[k] + 10, 100)`, иначе `conf = 0`.

## Деревья 0x180019a30 / 0x18001fdd0

6,7 и 8,4 КБ сравнений/переходов над ~12 полями записи, без вызовов. Перенесены как списки правил
`if (условия над полями записи) conf/status = 0;` в терминах полей `GoodixChicagoMatchScoreRecord` порта.
Правила получены структурированием кода DLL инструментом `tools/algo/lift_rules.py` (символьное исполнение
пролога, свёртка профиля params, «правило» = конус условий до записи флага и точка продолжения по
постдоминаторам; общие хвосты `conf = 0; goto конец` компилятора разведены по правилам) — это средство RE,
как декомпилятор; корректность подтверждается не им, а `reeval_difftest` против DLL. Повторная генерация:

```sh
cd tools/algo
../../.venv/bin/python lift_rules.py 0x180019a30 match_reeval_conf_tree_type24 params conf 3c=24 40=1 44=0 0=0 4=0
../../.venv/bin/python lift_rules.py 0x18001fdd0 match_reeval_status_tree_type24 params conf status 3c=24 40=1 44=0 0=0 4=0
```

Некоторые правила содержат недостижимые конъюнкции (например `t0 >= 390 && t0 < 370`) и пороги, которые
не наблюдаемы (следующее правило даёт тот же эффект) — это свойство исходных деревьев, не ошибка.

## Что осталось (не бит-в-бит)

Сверка 26-словных записей в точке префильтра (DLL `dll_match_trace.py` vs MTRACE), N=12: из 72 записей,
оценённых обеими сторонами, 7 различаются по геометрии/метрикам:
- 4 записи: у DLL rec+8 ≠ 0 и rec+4 выше — сработал **проход 2 геометрии 0x180024e10** (не перенесён),
  отсюда другие transform, selector/agreement/coverage и флаги формы (probe 0 idx 7, 2/11, 7/1, 16/5);
- probe 44 idx 6: selector 128 (DLL) против 200 при равной геометрии; probe 2 idx 9: selector 211 против 227
  и penalty_flag_b — вероятно, другой transform после второй попытки 0x180057ed0/0x18005ae30;
- probe 21 idx 10: inliers 5/7 (DLL) против 4/6 при равных selector/agreement — первая геометрия
  (0x1800594d0 после пар 0x18005a4f0). На N=15 та же запись 6/8 против 5/7 → genuine 21 DLL 25, порт 0.
- Величина положительного score (ratio) и коды отрицательных в 6–9 пробах — следствие того же.

## Чекпоинт (работа над остатком, 2026-09-28)

- `cmp_match.py --score <dll_trace>`: сверка score и выбранного подшаблона (DLL: последний `SEL i` в
  трассе `dll_match_trace.py` = result+0x648, пишется в 0x180029e9c). Базово N=12: 6 проб отличаются.
- Разбор прохода 2 0x180024e10 (тип 24): если rec+0 ≤ 8 и rec+4 ≤ 8: при rec+4 > 3 берётся
  преобразование прохода 1, иначе две попытки 0x18005b110 → 0x18001f2f0 (лучшая; rec+0 = max);
  при ≥ 3 inliers — направляемые соответствия 0x180059c20 (0x18005a810 ×2: окно 0x1500, отступ 5,
  расстояние min(ham(g+0x28,p+0x28), ham(g+0x28,p+0x30)) ≤ 16; выбор 40:38) → геометрия → n2.
  n2 > n1: метрики 0x180050730 (замена как в попытке 2 прохода 1, но без угла), перекрытие
  0x18005a160, форма 0x180053740 (сдвиг < 0x28f6, масштаб 234..281), затем
  `(mp>40&&cnt≥24)||(mp>45&&cnt≥12)||mp>75||n2>16` → rec+8 = n2, rec+0x28/0x2c, перекрытие в rec+0x124.
  **Хвост всегда:** rec+0x28 > 30 и mean_distance перекрытия (rec+0x134) < 10 → rec+0, rec+4 += 1
  (≤ 31). Это и есть probe 21 idx 10 (4/6 → 5/7), т.е. задача 2 — не первая геометрия.
- Путь rec+4 ≤ 3 (0x18005b110) даёт rec+8 > 0 на N=15 (probe 9) и N=20 (probe 10, 13, 54) — нужен.
